# Inventory maintenance

The repo tracks which Hisense VIDAA firmware generations are compatible
with which capabilities (pairing, launcher, file-bridge traversal/write,
root) using a single source of truth: `docs/research/inventory.json`. Human tables
(README tested-models matrix, playbook status table) are *generated* from
it — never hand-edit them.

## When a report arrives

Collect, in this priority: model, region, SoC (`Hisense_GetChipSetName`),
VIDAA OS (`Hisense_GetOSVersion`), firmware id
(`Hisense_GetFirmWareVersion`), build date, `transport_protocol`
(SSDP descriptor — see docs/research/TESTED-MODELS.md for field guidance), browser
engine/version, tester handle, and per-capability evidence. Negative
results and dead ends are first-class — a closed lane on one generation
is what tells the next owner where to dig.

## Workflow

1. **Update `docs/research/inventory.json`.** One object per firmware generation
   (not per unit — dedupe same-generation reports by extending
   `tested_by`). Status vocabulary per capability, exactly:
   `working | gated | closed | open | armed | achieved | blocked | untested | n-a`.
   **One token per capability — never prose.** The measurement behind a token
   goes in the row's optional `capability_detail` object, keyed by the same
   capability names; `scripts/gen-inventory.py` renders it into
   `docs/research/TESTED-MODELS.md`, and `scripts/check.sh` fails on a value
   outside the vocabulary. Keep `notes` to facts with evidence pointers.
   Format `tested_by` entries using platform prefixes or objects to generate
   direct links without ghost-mentions:
   - GitHub: `"gh:username"` (renders `[@username](https://github.com/username)`)
   - Reddit: `"reddit:username"` or `"u/username"` (renders `[u/username](https://reddit.com/user/username)`)
   - Custom: `{"name": "...", "url": "https://..."}`

   Example entry (abridged):

   ```json
   {
     "id": "09.60V.Q0612 (2026-07 EU_A)",
     "model": "55A60LEVS", "region": "EU_A",
     "soc": "MTK9603", "vidaa_os": "9.0",
     "transport_protocol": "3290",
     "browser": "Chromium 111.5563.5.1",
     "build_date": "2026-07-27",
     "tested_by": ["reddit:handle"],
     "capabilities": {
       "pairing": "working",
       "file_bridge_traversal": "closed",
       "file_bridge_write": "gated",
       "identity_gate": "working",
       "root": "blocked",
       "notes": "identity gate {appid,md5,permissions}; see findings/10"
     },
     "capability_detail": {
       "root": "Blocked at the fileWrite gate: no write primitive on this build."
     }
   }
   ```

2. **Regenerate the tables.**

   ```sh
   python3 scripts/gen-inventory.py            # rewrites README, playbook, tested-models
   python3 scripts/gen-inventory.py --check    # CI-style: fails if stale
   ```

   Never hand-edit the markdown between `<!-- INVENTORY:START -->` /
   `<!-- INVENTORY:END -->`, or between `<!-- INVENTORY_DETAIL:START -->` /
   `<!-- INVENTORY_DETAIL:END -->` markers.

3. **Narrate material changes** in
   `docs/research/10-patched-firmware-playbook.md` (a new root, a closed
   lane, a technique) — one short section with the evidence pointer.
   New firmware *rows* need no narrative; new *techniques* do.

4. **Reconcile the methods catalogue.** `docs/research/exploits.json` +
   `docs/research/EXPLOITS.md` (generated by `scripts/gen-exploits.py`) track
   per-method evidence with levels (verified / community reported /
   hypothesis / untested). The split: **inventory.json = per-TV status,
   exploits.json = per-method catalogue.** A new root chain goes in both;
   a capability regression only in the inventory.

5. **Commit and push.** The repo is shared between sessions —
   `git pull --rebase` before pushing.

6. **Draft the community reply** if the report came from the thread:
   brief, evidence-linked, always invite the matrix row or findings PR,
   and thank for negative results explicitly.

## Field values

docs/research/TESTED-MODELS.md documents where each value comes from (SSDP
descriptor for `transport_protocol`, bridge calls for SoC/firmware).
If the reporter lacks a field, leave `"?"` — never guess.

## Guardrails

- Own TVs only; redact identifiers (MACs, serials, tokens) from anything
  committed — keys and tokens never leave `server/keys/`.
- Unverified root claims stay `in progress`/`untested` until evidence
  lands; live-verified claims say how (log excerpt, artifact, command).
- Vendor binaries/images are not committed to the public repo.
- The `capabilities` key set is fixed; propose additions by editing this
  skill in the same PR and updating the legend in `inventory.json`.
